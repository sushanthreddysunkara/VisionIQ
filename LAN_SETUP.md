# Run VisionIQ on a LAN

Run both services on the computer that can reach the configured MySQL server.
The Django API listens on port `8000`; Vite proxies `/api`, `/socket.io`,
`/images`, and `/evidence` to it.

## 1. Configure the backend

In PowerShell, from the repository root:

```powershell
if (-not (Test-Path backend\.env)) { Copy-Item backend\.env.example backend\.env }
```

Edit `backend\.env` with the existing MySQL connection details. Set
`DJANGO_SECRET_KEY` to a random value of at least 32 characters, and set
`FRONTEND_URL` to the Vite origin(s), comma-separated if multiple origins are
used. Keep `DJANGO_DEBUG=false`.

## 2. Create the Python environment and install dependencies

```powershell
py -3.14 -m venv backend\.venv
backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

## 3. Check and safely apply migrations

```powershell
Set-Location backend
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py migrate --plan
.\.venv\Scripts\python.exe manage.py migrate --noinput
```

The existing telemetry and network tables are mapped as unmanaged Django
models; the migration does not recreate or alter them. The initial migration
creates the legacy `users` table only if it is absent. Existing user rows are
not changed.

If administrator accounts need to be bootstrapped, configure non-placeholder
`ADMIN1_*` values in the local environment file, then run:

```powershell
.\.venv\Scripts\python.exe manage.py seed_users
```

This command creates missing accounts and never changes existing passwords.

## 4. Start the Django API

From `backend\`:

```powershell
.\.venv\Scripts\python.exe manage.py serve --host 0.0.0.0 --port 8000
```

ASGI is required for the existing Socket.IO live telemetry events. The default
`HOST` and `PORT` values from `backend\.env` can be used by omitting the
arguments.

## 5. Start the React frontend

In a second PowerShell window:

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run dev -- --host 0.0.0.0
```

## 6. Open from another computer

Find the host computer's IPv4 address with `ipconfig`, then open:

```text
http://<host-ip>:5173
```

For a frontend hosted separately from Vite, set `VITE_API_URL` to the Django
origin, for example `http://192.168.1.25:8000`, and add that frontend origin to
`FRONTEND_URL`.

Allow inbound TCP ports `5173` and `8000` only on a trusted private LAN. Do not
expose the development server or database port to the public internet.

## Troubleshooting

- **Database connection refused:** confirm MySQL is reachable from the backend
  computer and the `MYSQL_*` values match the existing database.
- **CORS error:** add the exact browser origin, including scheme and port, to
  `FRONTEND_URL`, then restart Django.
- **Missing telemetry/network table:** the migration intentionally does not
  create these pre-existing tables. Restore the configured database/schema;
  do not replace it with SQLite or drop/recreate it.
- **Ollama unavailable:** query parsing uses the existing deterministic
  fallback. Start Ollama and configure `OLLAMA_HOST`/`OLLAMA_MODEL` to use it.
- **Camera feed unavailable:** remote stream sources must be accessible to the
  user's browser; no camera video is generated by the backend.
